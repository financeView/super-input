# LLM 辅助中文拼音输入法（macOS）设计文档

- **日期**：2026-09-22
- **状态**：已与用户逐节确认
- **项目代号**：super-input

## 1. 背景与目标

macOS 自带中文输入法上下文纠错能力弱（n-gram 级排序），前后鼻音等模糊音场景大量错字；搜狗类商业输入法靠超大词库+云服务，黑盒且隐私存疑。目标：做一个**LLM 上下文重排的拼音输入法**，核心场景是模糊音（前后鼻音等）的上下文纠错。

**核心问题拆解**：
- 第一层：模糊音**召回**（打 `fen` 能出「风」）——librime 原生支持（`speller/algebra`），成熟技术，非本项目重点。
- 第二层：上下文**重排**（`fen` 的候选里「风」何时排第一）——LLM 的真正用武之地，本项目核心。

## 2. 需求决策记录（brainstorm 定稿）

| 决策点 | 结论 |
| --- | --- |
| 定位 | 自用+同事使用；内部安装（clone 手动装，无公证需求）；需通用性/可配置性 |
| LLM 路线 | 本地 MLX 小模型为主 + 云 BYOK 降级链 |
| 改字权限 | 分级可选：L0 严格模糊音等价类（默认）/ L1 同音词优化（可配置） |
| 触发机制 | 逐键=快速通道（librime，<10ms）；停顿（防抖 500ms）触发 LLM。**不做逐键调 LLM**——流式 API 解决的是输出侧首 token 等待，输入侧每键仍是完整请求往返（本地 50-300ms / 云 300ms-1s），追不上 100-300ms/键的打字节奏；且 token 粒度与拼音音节错位，半截拼音碎片输入质量反差 |
| LLM 角色 | 分级：L1 重排（默认，零幻觉，只能在候选内选）→ L2 整句解码（升级，需过拼音一致性校验） |
| v1 范围 | 全量：L1 + L2 + 校验层 + 云 BYOK 一步到位 |
| 平台壳 | Fork Squirrel（rime 的 macOS 前端，GPL-3，纯 Swift，活跃）；内部使用不分发，GPL 无义务触发，未来开源无障碍 |

## 3. 总体架构（三进程）

```
┌─────────────────────────────────────────────────────┐
│ Squirrel.app（fork，GPL，改动控制在几百行）              │
│  IMK 壳 + librime 引擎（快速通道）+ 候选窗 UI           │
│  新增：注入点（候选更新路径）+ 防抖器 + IPC 客户端        │
└──────────────┬──────────────────────────────────────┘
               │ localhost IPC（XPC 或 HTTP）
               ▼
┌─────────────────────────────────────────────────────┐
│ rerank-service（全新自研核心）                          │
│  · L1 重排器：top-N 候选 + 前文 → 排序（默认）          │
│  · L2 整句解码器：拼音串 + 前文 → 整句（升级）          │
│  · 校验层：拼音一致性逐字比对（硬闸门）                  │
│  · 推理后端：本地 MLX（Qwen2.5 4bit）→ 云 BYOK 降级链    │
│  · 信任分级：L0/L1                                     │
└─────────────────────────────────────────────────────┘
```

**边界原则**：
- Squirrel fork 只加不改：注入点位于「librime 返回候选 → 刷新候选窗」路径；fork 面积最小化，跟上游好合并。
- 模型绝不进 IME 进程（IME 是 in-proc 加载进每个宿主应用的，内存会 ×N）——rerank-service 独立进程，launchd 守护。
- 逐键路径零新增延迟：IPC 只在停顿后发生。

**配置三层**：
1. librime schema yaml（模糊音对、双拼方案——原样继承 rime 生态）
2. rerank 配置（信任级 L0/L1、防抖窗口、云开关、模型规格）
3. BYOK 凭证（钥匙串存储，TypeFree SecretStore 模式）

## 4. 数据流与重排协议

一次典型输入 `jintianwoquchaoshimaimaidongxi` 的时序：

```
逐键（100-300ms/键）：每键 → librime 解码（含模糊音展开）
  → 候选窗即时刷新（<10ms）；防抖器每键重置 500ms

停顿触发（≥500ms 无按键）：
  Squirrel 组装请求：
    { 前文: 已上屏最后 ~50 字
      拼音串: 未提交完整拼音（含模糊音标记）
      候选: librime top-20（按音节分组的 lattice 路径）
      用户已选: 手动挑过并回改的部分 }
  → rerank-service

L1 重排（默认，本地，目标 <800ms）：
  prompt：前文 + 候选列表 → 重排 + 置信度
  约束：只能在候选内选择（构造上零幻觉）
  输出：重排后顺序 + 整句拼接

质量闸门：L1 首选与快速通道首选不一致且置信度 > 高阈值 → 升级 L2
  L2 整句解码（本地/云）：前文 + 完整拼音串 → 整句
  校验层（硬闸门）：输出逐字转拼音（含模糊音等价类）
    与输入拼音串比对，任一字不符 → 丢弃，回退 L1
  信任级 L0：等价类内替换也需拼音匹配；L1：同音字校验放宽

响应回程：组合串 hash 未变 → 应用；变了 → 丢弃（过期响应）

应用方式（信任核心）：
  新首选替换原首选，原首选降为第二位
  用户按数字键选原首选 → 记「用户覆盖」负样本
  退格 → 回退快速通道排序
```

**协议要点**：
- 过期响应丢弃：用户已继续打字时旧结果绝不应用，防候选窗跳变打手。
- 两级闸门 + 一个出口：LLM 只有证明自己对了才有改字权。
- 前文取已上屏文本，不含未提交串（未提交串本身是被重排对象）。
- 用户覆盖负样本本地存储，长期喂排序（v2 个性化微调的原料）。

## 5. 错误处理矩阵

| 故障 | 行为 |
| --- | --- |
| rerank-service 未启动/崩溃 | 纯快速通道，退化为普通 librime 输入法；launchd 自动拉起 |
| 本地模型超时（>800ms） | 丢弃本次重排，维持快速通道结果 |
| 本地质量闸门不达标频繁 | 降级链：本地 → 云 BYOK；云未配 → 维持本地 |
| 云 429/网络断 | 指数退避重试 1 次，失败回退本地结果 |
| L2 校验失败 | 回退 L1 结果 |
| 组合串已变 | 丢弃在途响应，不打扰 |
| 防抖期间用户翻页/手选 | 取消在途重排（用户意志 > LLM 意见） |

## 6. 测试策略（自底向上三层）

1. **离线重排基准（最先做，不碰 IME）**：收集前后鼻音易错句 200+ 条测试集，跑 rerank-service 的 L1/L2。指标：首选正确率 vs librime 基线（项目成败数字）、校验层拦截率、幻觉率（校验漏放行的错字，人工抽检）。**此基准在写任何 Squirrel 代码之前验证 LLM 路线本身值不值。**
2. **延迟基准**：本地 MLX L1 P95 < 800ms、L2 < 2s；超标则降模型规格或调防抖窗口。
3. **集成手感测试**：同事环境 5-10 台日用两周；收集改字被回退率（信任信号）与负样本量。

## 7. 验收标准（v1 完成定义）

- 测试集首选正确率 ≥ librime 基线 +15 个百分点（跑完基准后校准，先立此目标）
- 严格模式（L0）零「改坏」路径：等价类约束从构造上保证不会改出非法字，改错仅是选词错（与普通输入法同级）
- 逐键路径延迟零回归（IPC 只在停顿后发生；CI 加注入前后延迟对比）
- 三进程崩溃互不影响（杀 rerank-service 打字不受任何影响）

## 8. 许可与合规

- Squirrel：GPL-3 fork。内部使用（不分发）无 copyleft 义务触发；未来若开源，GPL 合规即可。
- librime：BSD-3（Squirrel 内嵌）。
- 云 BYOK：每用户自己的 API Key，钥匙串存储，请求直连服务商（TypeFree 模式，不经任何中转）。
- 不做对外分发（v1 不涉及签名/公证/App Store）。

## 9. 风险与遗留

- **信任风险（最大）**：L2 整句解码未经日用轻验就上——用「默认 L1、L2 需高置信 + 校验 + 可回退」兜底，两周手感测试观察回退率。
- 上下文获取依赖 IMK 能拿到的已上屏文本，不同应用支持度不一（Squirrel 已处理大部分兼容，但个别应用前文可能为空——L1/L2 在空上下文时自动退化为纯快速通道排序）。
- v2 候选（明确不在 v1）：个性化微调（负样本训练）、分级切换的自动学习、Windows TSF 版。
