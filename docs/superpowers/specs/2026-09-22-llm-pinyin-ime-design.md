# LLM 辅助中文拼音输入法（macOS）设计文档

- **日期**：2026-09-22（v3，2026-09-23 修订：吸收独立 review 8 项 major 修正）
- **状态**：已与用户逐节确认；三轮 review（人工×2 + 独立 subagent×1）完成
- **项目代号**：super-input

## 1. 背景与目标

macOS 自带中文输入法上下文纠错能力弱（n-gram 级排序），前后鼻音等模糊音场景大量错字；搜狗类商业输入法靠超大词库+云服务，黑盒且隐私存疑。目标：做一个**LLM 上下文重排的拼音输入法**，核心场景是模糊音（前后鼻音等）的上下文纠错。

**核心问题拆解**：
- 第一层：模糊音**召回**（打 `fen` 能出「风」）——librime 原生支持（`speller/algebra`），成熟技术，非本项目重点。
- 第二层：上下文**重排**（`fen` 的候选里「风」何时排第一）——LLM 的真正用武之地，本项目核心。

## 2. 需求决策记录（brainstorm 定稿 + review 修订）

| 决策点 | 结论 |
| --- | --- |
| 定位 | 自用+同事使用；内部安装（clone 手动装，无公证需求）；需通用性/可配置性 |
| 硬件底线 | 16GB+ 主流档（M 系列）；本地模型 1.5B-3B 4bit 起步，基准阶段产出延迟-模型尺寸曲线后定档 |
| LLM 路线 | 本地 MLX 小模型为主 + 云 BYOK 降级链 |
| 触发机制 | 逐键=快速通道（librime，<10ms）；停顿（防抖 500ms）触发 LLM；**最小触发门槛 ≥2 音节**（云成本与无意义请求控制）。不做逐键调 LLM（流式 API 解决输出侧首 token 等待，输入侧每键仍是完整往返；token 粒度与音节错位） |
| LLM 角色（v3 重设计） | **L1 似然打分**（默认）：对 top-20 候选逐个算 log P(候选\|前文) 取 argmax——纯 prefill 无解码（延迟可控）、构造上零非法字、置信度=logprob 差（可校准、可设阈值）。前置条件：跨请求 KV 前缀缓存（mlx-lm 现状**基准第一项实测**，不支持则自研打分循环或退生成式重排）。**L2 整句解码**（升级）：前文+拼音串→整句，须过拼音校验硬闸门 |
| 信任分级（v3 重定义） | T0（默认）= 校验层本身：输出每字须对应输入音节（模糊等价类内、不校声调）；对 L1 恒真（librime 候选天然满足），只约束 L2。T1 = 在 T0 基础上额外允许 **≤2 字无音节对应的插入/删除**（的/了/儿等虚词、儿化、音变），超出仍拦截；适合口语化整句场景，可按用户配置 |
| v1 范围 | 全量：L1 + L2 + 校验层 + 云 BYOK 一步到位 |
| 平台壳 | Fork Squirrel（rime 的 macOS IMK 前端，GPL-3，纯 Swift，活跃）；内部使用不分发，GPL 无义务触发，未来开源无障碍 |

## 3. 总体架构（进程模型）

```
┌─────────────────────────────────────────────────────┐
│ Squirrel.app（fork，GPL）                              │
│  · IMK in-proc 实例 ×N：每宿主应用一份（COM in-proc 模型）│
│  · librime 引擎（快速通道）+ 候选窗 UI                  │
│  新增：候选更新路径注入点 + 防抖器 + IPC 客户端          │
│    + 选择键拦截与索引重映射（见 §4.3）                   │
└──────────────┬──────────────────────────────────────┘
               │ localhost HTTP IPC（127.0.0.1 固定端口+版本头）
               │ 鉴权：launchd 启动时生成随机 token 写 0600 文件，
               │       请求携带该 token（防本机进程抢占）
               ▼
┌─────────────────────────────────────────────────────┐
│ rerank-service（全新自研核心，常驻守护）                  │
│  · L1 似然打分器：候选×前文 → logprob 排序              │
│  · L2 整句解码器：拼音串+前文 → 整句（须过校验）         │
│  · 校验层：拼音音节比对（硬闸门，规则见 §4.4）           │
│  · 推理后端：本地 MLX（1.5B-3B 4bit）→ 云 BYOK 降级链    │
│  · 启动即模型 warmup（4GB 级模型加载需数秒-十数秒，       │
│    无 warmup 则开机后全部撞硬限被丢；设加载宽限期）        │
└─────────────────────────────────────────────────────┘
```

**进程计数修正（v3）**：2 个常驻进程（Squirrel.app、rerank-service）+ 每宿主应用一份的 IME in-proc 实例。模型绝不进 IME 进程（内存 ×N）；rerank-service 由 launchd 守护。逐键路径零新增延迟：IPC 只在停顿后发生。

**fork 面积修正（v3）**：原「只加不改几百行」不成立——选择键拦截+索引重映射+焦点/会话跟踪+防抖+IPC 客户端，现实量级 **1-2k 行**。仍遵守「注入点集中、跟上游好合并」原则。

**配置三层**：
1. librime schema yaml（模糊音对、双拼方案；**page_size 调至 20** 供 L1 打分取材，候选窗 UI 只显示前 N——不改词表与算法配置）
2. rerank 配置（信任级 T0/T1、防抖窗口、云开关、模型规格、前文窗口字数）
3. BYOK 凭证（钥匙串存储，TypeFree SecretStore 模式）

**单一事实源**：模糊音等价类由 rerank-service **直接解析同一份 schema yaml** 推导，不另建配置（两边漂移 = 校验误杀/漏放）。

## 4. 数据流与重排协议（v3 重写）

### 4.1 载荷（基于 librime 真实 API 面）

librime 前端可得的是 `RimeGetContext` 的**扁平候选数组**（text+comment）与 preedit 文本；lattice 是引擎内部结构，**API 不暴露**。因此请求载荷为：

```
{ session_id:           IMK 会话标识（per-宿主）
  request_id:           单调递增（多次停顿在途时对回响应）
  原始击键串:           fork 自记的用户按键序列（双拼下即击键序列，
                        非 Web 拼音串——服务端按 schema 双拼规则转换）
  preedit 快照:         当前组合串文本 + 光标位置
  扁平候选:             当前页及可达页的候选数组（text/comment/序号）
  前文:                 §4.2 定义
  用户已选标记:          手动挑过并回改的部分 }
```

### 4.2 前文（v3：自给优先）

- **本 IME 提交过的文本：commit 回调天然全量持有**——前文的主要来源，自给自足。
- 仅「非本 IME 输入的历史」（粘贴、切换输入法之前）需向宿主查询，跨应用拿不全时有多少取多少。
- 取法：从句首到光标的已上屏文本，**含标点**；截断窗口默认 200 字（可配置）。对 LLM 是低成本上下文，宁多勿少；但延迟超标时按实测自适应收缩。

### 4.3 时序与守卫

```
逐键（100-300ms/键）：每键 → librime 解码（含模糊音展开）
  → 候选窗即时刷新（<10ms）；防抖器每键重置 500ms
  前文缓冲随每次 commit 追加

停顿触发（≥500ms 无按键 且 ≥2 完整音节）：
  组装 §4.1 载荷 → rerank-service

L1 似然打分（默认，本地）：
  对 top-20 候选逐个算 log P(候选|前文)，argmax
  KV 前缀缓存复用前文（mlx-lm 支持度 = 基准第一项实测）
  输出：最佳候选 + logprob 差（置信度）
  约束：只能在候选内选择——零非法字，
        但会继承候选的词切分错误（lattice 切分错则 L1 无法纠正，
        这正是 L2 存在的动机）

升级判定：L1 argmax ≠ 快速通道首选 且 logprob 差 < 高阈值
  （打分不确定才升级，而非"更自信才升级"）
  → L2 整句解码（本地/云）：前文 + 完整拼音串 → 整句
  → 校验层（§4.4）；L1 结果暂缓应用，与 L2 合并后一次应用（防级联二次跳变）

响应回程——守卫元组校验，任一失配即丢弃，绝不打扰：
  ( session_id 一致
    组合串 hash 未变（用户没继续打）
    preedit 光标位未变（←/→ 可移动光标，hash 拦不住）
    翻页状态未变
    request_id 为最新
    该会话仍持有键盘焦点 )   ← 防跨应用竞态：A 停顿触发请求→切到 B→
                                响应回来，若不查焦点会打进失焦会话

应用（v3：选择键拦截，非显示层重排）：
  空格/回车/数字键按下时：拦截 → 重映射到重排首选的 librime 原索引
  → 调 RimeSelectCandidate（librime 的空格提交走引擎内部首选，
    只改显示层会被空格静默短路——这是 v1 必须做对的点）
  用户按数字键选了非 LLM 首选 → 记「用户覆盖」负样本
  退格 → 回退快速通道排序
```

### 4.4 校验层规则（v3 钉死）

- **预处理**：L2 输出限汉字+白名单标点；标点剥离或映射后比对（LLM 整句几乎必带标点，不处理则 L2 永远整体误杀）。
- **对齐**：DP 对齐允许 1 音节对多字（儿化：输入 `nar` 一音节、输出「哪儿」两字；及有限枚举的音变）。
- **比对**：音节层匹配（声母+韵母，**模糊等价类内视为相等**）；不校声调；多音字任一读音匹配即过。
- **前缀截取**：停顿常发生在音节中间（打到 …maim 停下）——只取**完整音节前缀**参与比对与解码，尾部残缺留待下次停顿。
- **信任级**：T0 = 上述规则本身（每字须对应音节）；T1 = 额外允许 ≤2 字无音节对应插入/删除（虚词/儿化/音变），超出拦截。
- 任一校验失败 → 回退 L1 结果；L1 也失败 → 维持快速通道。

## 5. 错误处理矩阵（v3 修订）

| 故障 | 行为 |
| --- | --- |
| rerank-service 未启动/崩溃 | 纯快速通道，退化为普通 librime 输入法；launchd 自动拉起 |
| rerank-service 冷启动/加载模型中 | 宽限期内直接返回快速通道结果（不重排），warmup 完成恢复 |
| 本地模型超时（>1500ms 硬限；P95 目标 800ms） | 丢弃本次重排，维持快速通道结果 |
| 本地超时率超标 | **降级触发器 = 超时率滑动窗口**（如 5 次里 3 次超硬限 → 本会话降云）；小模型自报置信度校准差，不作触发器；云未配则维持本地 |
| 云 429/网络断 | 指数退避重试 1 次，失败回退本地结果 |
| L2 校验失败 | 回退 L1 结果 |
| 守卫元组任一失配 | 丢弃在途响应，不打扰（含跨应用切焦点、翻页手选后空窗） |
| 防抖期间用户翻页/手选 | 取消在途重排（用户意志 > LLM 意见） |

## 6. 测试策略（自底向上三层）

1. **离线重排基准（最先做，不碰 IME）**：
   - **基础设施工效验证（第一项）**：mlx-lm 跨请求 KV 前缀缓存支持度；1.5B/3B 4bit 在 16GB M 系列的真实 prefill/解码吞吐（**产出延迟-模型尺寸曲线**）。
   - 测试集：前后鼻音易错句 200+ 条。
   - 指标：**召回上限**（正确答案在 top-20 内的比例——L1 的结构性天花板）；**首选正确率 vs librime 基线**（基线必须跑**同一模糊音 schema**，否则对比不公平）；校验层拦截率；幻觉率（校验漏放行错字，人工抽检）。
   - **此基准在写任何 Squirrel 代码之前验证 LLM 路线本身值不值。**
2. **延迟基准**：本地 MLX L1 P95 < 800ms（硬限 1500ms）、L2 P95 < 2s；超标则沿延迟-尺寸曲线降模型规格或调防抖窗口。
3. **集成手感测试**：同事环境 5-10 台日用两周；收集改字被回退率（信任信号）与负样本量。

## 7. 验收标准（v1 完成定义）

- 测试集首选正确率 ≥ librime 基线（同 schema）+15 个百分点，**且对照召回上限解读**（若上限本身只比基线高 18pt，则目标应转为"达到上限-3pt 内"之类，跑完基准校准）
- T0 模式零「改坏」路径：校验规则从构造上保证不会改出非法字；T1 的有界编辑（≤2 字）也在拦截范围内可控
- 逐键路径延迟零回归（IPC 只在停顿后发生；CI 加注入前后延迟对比）
- 进程隔离：杀掉 rerank-service，打字不受任何影响（退化为纯 librime）；rerank-service 崩溃不牵连宿主应用
- 空格提交路径正确性测试：重排应用后，空格提交的必须是重排首选（M1 回归测试）

## 8. 许可与合规

- Squirrel：GPL-3 fork。内部使用（不分发）无 copyleft 义务触发；未来若开源，GPL 合规即可。
- librime：BSD-3（Squirrel 内嵌）。
- 云 BYOK：每用户自己的 API Key，钥匙串存储，请求直连服务商（TypeFree 模式，不经任何中转）；触发门槛 ≥2 音节控制成本。
- 不做对外分发（v1 不涉及签名/公证/App Store）。

## 9. 风险与遗留

- **KV 缓存实测（新，L1 设计前置条件）**：mlx-lm 跨请求前缀缓存若不可用，L1 退化为自研打分循环或生成式重排（延迟预算重算）——基准阶段第一项解决。
- **选择键拦截的兼容面（新）**：拦截空格/回车/数字键重映射索引，需在各类应用（终端、Electron、远程桌面）验证无副作用——集成测试重点项。
- **信任风险**：L2 整句解码未经日用轻验就上——用「默认 L1、L2 需 logprob 差小于阈值 + 校验 + 可回退」兜底，两周手感测试观察回退率。
- **上下文风险（v3 大幅缓解）**：本 IME 提交的前文自给（commit 回调全量）；仅非本 IME 历史（粘贴/切换前）依赖宿主查询，拿不全有多少取多少，空上下文时 L1/L2 自动退化为纯快速通道排序。
- v2 候选（明确不在 v1）：个性化微调（负样本训练）、升级判定的自动学习、Windows TSF 版。
